# RANGER-DTLx Adapter Specification

> 🌐 中文版：[ranger_dtlx.md](ranger_dtlx.md)

- **Tool**: RANGER-DTLx (DTL reconciliation + AggregateRanger), from `RANGER-DTLx-代码`.
- **Adapter**: `maxtic_next.constraints.adapters.ranger_dtl` (`RangerDTLAdapter` /
  `convert_from_ranger_dtl`), parsing core `_recon_report` (shared with ARTra).
- **Tool name (registry / CLI)**: `ranger` (`--from ranger`).

## 1. Real Output Format (verified from source code)

RANGER-DTLx prints a human-readable reconciliation report gene node by gene node. The
block header is printed by
`RANGER-DTLx-代码/Ranger-DTLx/DTL-algorithm.h:2170`; transfer event lines, however, are
generated by **one of three branches in the same file**, and the parent fragment varies
with the type of the mapped node — `:1840-1841` (the mapped node is an `isEdge` edge
node) prints `Transfer, Mapping --> …, Edge, Parent = …, Recipient --> …`, `:1864-1865`
(the mapped node is an `isDummy` dummy node) prints
`Transfer, Mapping --> …, Parent = …, Recipient --> …`, and `:1886` (the `else` of the
`isDummy` test, where ordinary species nodes are printed) prints neither. The example
below is written consistently in the `:1840-1841` branch (the one carrying `Edge,`):

```
 ------------ Reconciliation for Gene Tree 1 (rooted) -------------
g1_0: Leaf Node
m1 = LCA[g1, g2]: Speciation, Mapping --> 59, Edge, Parent = 69
m2 = LCA[g3, g4]: Duplication, Mapping --> 61, Edge, Parent = 65
m3 = LCA[g1, g4]: Transfer, Mapping --> 61, Edge, Parent = 65, Recipient --> 62
```

> Splitting the file into blocks matches only the `Reconciliation for Gene Tree` **prefix**
> (`_recon_report._BLOCK_RE`), so both the upstream `(rooted)` header and the abbreviated
> `Reconciliation for Gene Tree 1:` used by the sample in this repository
> (`tests/data/ranger_dtl_example/FAM1.dtl`) are recognized.

A file may contain multiple `Reconciliation for Gene Tree N` blocks.
⚠️ **The block count is not the sampling denominator**: upstream prints one block header
per input **gene tree** — a block is another tree, not another sample. The support
denominator now prefers the count **declared by the report itself**,
`Total number of optimal solutions: N`
(`weight_semantics = support_over_declared_samples`);
when the report declares **several** values (RANGER-DTLx prints one line per gene tree),
the **maximum** is used as the denominator and a warning is recorded; only when there is
more than one block and all blocks share an identical leaf set (genuinely repeated
reconciliations of the same family) does it fall
back to `support_over_replicate_blocks` (ecceTERA does not check the leaf set of its
blocks, see [eccetera.en.md](eccetera.en.md) §2); when neither holds, weights are emitted as
**integer counts** (`integer_count`), and it is made explicit that the
`--ale-min-support` threshold then **has no [0,1] support semantics**.

> **Format verified**: this adapter parses exactly the `Mapping --> / Recipient -->`
> records RANGER-DTLx really writes out; the fields were checked item by item against
> the upstream source and samples.

## 2. Field Extraction and Semantic Mapping

- A line is recognized as a transfer only when it contains **both** `Mapping` and
  `Recipient` (`parse_transfer_line`; only transfer events carry `Recipient`, loss /
  duplication / speciation lines do not);
- `Mapping --> D` (up to the comma / end of line) → **donor** D; `Recipient --> R`
  (first token) → **receptor** R;
- Produces constraint `(D, R)`, semantically identical to ALE's `T@D->R`;
- Leaf lines `X: Leaf Node` are used for family size estimation;
- Speciation / Duplication / Leaf lines contain no `Recipient -->` and are ignored
  automatically.

## 3. Support / Weight / Distance

Per-block counting → reciprocal subtraction →
`support = count / denominator` (denominator = the number of samples, i.e. the tool's
declared value; see the denominator ruling in §1) → keep
`> min_support`;
`distance = distance_from(receptor, donor)`; **self-loop exception**: when
`donor == receptor`, `distance = None` is written (no distance information) and the
constraint is not removed by `--min-transfer-distance`.
The donor endpoint is the **donor itself** of `Mapping -->`
(`donor_endpoint_convention = donor_itself`), **one species level away** from ALE's
`parent_of_donor`, and must not be added directly onto ALE constraints.

## 4. Error Handling and Validation

| Situation | Handling |
|-----------|----------|
| donor / receptor not in the species tree label set | The transfer is dropped (no false constraints) |
| Endpoint-drop observability | Every dropped transfer is **counted by reason** (`dropped_by_label_miss`; numeric-ID resolution runs only on the ecceTERA path, so `numeric_id_resolutions` is always 0 here), a diagnostic summary is printed to stderr when the conversion finishes and the same dictionary is attached to `ConstraintSet.diagnostics`; an endpoint hit rate of **0** raises `LabelMismatchError`, and one below `min_endpoint_hit_rate` (default `0.5`) triggers a warning (`--quiet-adapters` only silences printing; counting and error raising are unaffected) |
| Family size (number of leaf lines) `<= min_family_size` | Skipped |
| Family size **probe failed** (no `X: Leaf Node` line in the report) | The `min_family_size` filter is **skipped** with a warning (`resolve_family_size_filter`) instead of wiping out all transfers |
| Transfers present but no block header | Block count recorded as 1 |
| Per-file exception in parallel mode / cache hit | Sequential fallback / reuse |

## 5. Known Limitations

- Endpoints are species labels (internal nodes are often numeric, e.g. `61`) and must
  match the species tree bootstrap labels;
- For AggregateRanger's multi-sample aggregation, either merge the samples into multiple
  blocks in the same file, or keep them in separate files and let the adapter sum across
  files.
- This section is a summary: the **complete semantics** of the endpoint levels, weight
  conventions and the diagnostics counters are governed by the normative semantic notes
  [README_semantics.md](../../src/maxtic_next/constraints/adapters/README_semantics.md) /
  [README_semantics.en.md](../../src/maxtic_next/constraints/adapters/README_semantics.en.md).

## 6. Usage

```bash
maxtic-next species.tree FAM1.dtl --from ranger --ale-min-family-size 5
```

```python
from maxtic_next.constraints.adapters import convert_from_ranger_dtl
cset = convert_from_ranger_dtl(species_tree, ["FAM1.dtl", "FAM2.dtl"], min_family_size=5)
```
