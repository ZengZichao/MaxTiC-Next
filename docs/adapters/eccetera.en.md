# ecceTERA Adapter Specification

> 🌐 中文版：[eccetera.md](eccetera.md)

- **Tool**: ecceTERA (DTL reconciliation), from `ecceTERA-代码`.
- **Adapter**: `maxtic_next.constraints.adapters.eccetera` (`EcceTERAAdapter` /
  `convert_from_eccetera`).
- **Tool name (registry / CLI)**: `eccetera` (`--from eccetera`).

## 1. Real Output Format (verified from source code): recPhyloXML

ecceTERA's structured reconciliation output is the **recPhyloXML** standard (Duchemin et
al. 2018), generated by
`ecceTERA-代码/src/DTLGraph.cpp:getRecPhyloXMLReconciliation`. Transfer events are
encoded as:

- **Donor** node:
  `<eventsRec><branchingOut speciesLocation="D"></branchingOut></eventsRec>`;
- The **receptor** child node that is transferred to:
  `<eventsRec><transferBack destinationSpecies="R"></transferBack>
  <speciation.../leaf.../></eventsRec>`.

```xml
<recPhylo>
 <recGeneTree><phylogeny rooted="true">
  <clade><name>1</name>
   <eventsRec><branchingOut speciesLocation="61"></branchingOut></eventsRec>
   <clade><name>2</name>
    <eventsRec><leaf speciesLocation="61" geneName="g1"></leaf></eventsRec></clade>
   <clade><name>3</name>
    <eventsRec><transferBack destinationSpecies="62"></transferBack>
               <leaf speciesLocation="62" geneName="g2"></leaf></eventsRec></clade>
  </clade>
 </phylogeny></recGeneTree>
</recPhylo>
```
The example above → constraint `61 -> 62`.

> **Format verified**: this adapter parses ecceTERA's real recPhyloXML output; the
> fields it reads were checked item by item against the upstream source and samples.

## 2. Field Extraction and Semantic Mapping

- Recursively traverse the `<clade>` tree, passing each parent node's
  `branchingOut speciesLocation` downward;
- For a child clade containing `transferBack destinationSpecies="R"`, the **parent**
  clade's branchingOut `speciesLocation="D"` is the donor → produce constraint `(D, R)`;
- Each `<recGeneTree>` is treated as one reconciliation block; `<leaf geneName>` counts
  toward the family size.
  ⚠️ The block count does **not** automatically serve as the support denominator:
  normalization by `support_over_replicate_blocks` applies only when all blocks share an
  identical leaf set; otherwise the weight is an integer count and the semantics are
  labeled honestly.

## 3. Support / Weight / Distance

Same as RANGER: per-block counting → reciprocal subtraction →
`support = count / declared sample count` → keep `> min_support`; the donor endpoint is
the **donor itself** of `branchingOut speciesLocation` (`donor_itself`), one species
level away from ALE's `parent_of_donor`.
`distance = distance_from(receptor, donor)`; **self-loop exception**: when
`donor == receptor`, `distance = None` is written (no distance information) and the
constraint is not removed by `--min-transfer-distance`.

## 4. Error Handling and Validation

| Situation | Handling |
|-----------|----------|
| Contains `<!DOCTYPE>` / `<!ENTITY>` | **Parsing refused** (guards against entity expansion / XXE; stdlib suffices, no defusedxml needed) |
| XML parse error | Returns empty (no crash) |
| donor / receptor not in the species tree | The transfer is dropped |
| Family size `<= min_family_size` | Skipped |

## 5. Known Limitations (Important)

- ecceTERA labels **internal species nodes** in recPhyloXML with their **own numeric node
  IDs** (leaves use names). These IDs **need not match** the species tree bootstrap
  labels that the user passes into MaxTiC — non-matching endpoints are filtered out by
  `valid_labels` (conservatively correct: no false constraints are produced, but recall
  may be reduced).
- Recommendation: align the species tree internal labels with ecceTERA's species naming,
  or rely only on leaf–leaf / label-consistent transfers.
- ecceTERA can also emit Sylvx / `.mr` formats; this adapter supports only standard
  recPhyloXML.

## 6. Usage

```bash
maxtic-next species.tree fam1.recphyloxml --from eccetera
```

```python
from maxtic_next.constraints.adapters import convert_from_eccetera
cset = convert_from_eccetera(species_tree, ["fam1.recphyloxml"], min_family_size=5)
```
